# 投資探究

企業決算を公式資料から読み、分析の変化を蓄積する閲覧専用サイト。GitHub Pages標準のJekyllを使用します。

## 更新手順

1. `_articles/` のMarkdownで記事を作成・改訂します。`company_id` は `_data/companies.json` のidと一致させます。
2. `published`（公開日）を維持し、改訂時は `updated` と本文の更新履歴を変更します。日付は引用符付きの YYYY-MM-DD。`announcement` は決算発表日です。
3. `conclusions` はトップと本文の要約、`segments` はSpaceX記事の図表と当期数値の管理元です。単位は億ドル。他社にはこの図を流用せず、それぞれの開示定義に合う表を使います。図の表示上限を超える場合は `_includes/segment-chart.html` の目盛り・説明・倍率を揃えて改訂します。
4. 出典の表・注記、数値、対象期間、独自計算式を照合し、変更を作業ブランチへ登録します。
5. Pull Requestで差分と検証結果を提示します。ユーザーの承認後にmainへマージし、Pagesのビルド・公開・表示を確認します。承認前にマージ・デプロイを行いません。

新しい決算は別記事にします。事実、会社の見通し、AI分析、本人の考察を区別し、本人の言葉を創作しません。未確認事項と未実施の株価評価は明記します。

記事一覧と公開済み・更新予定の銘柄数はMarkdownと企業データから自動生成します。企業データのtypeは日本株・米国株・ETF・J-REITを使用します。

## 公開と検証

Settings → Pages → Deploy from a branch → main / (root)。baseurlは `/investment-tankyu`。

ローカルでJekyllが利用できる場合は `jekyll build --baseurl /investment-tankyu`。公開後はトップ・記事・CSS・目次・出典を確認し、スマートフォンで表以外に横はみ出しがないこと、キーボードでリンクへ移動できることを確認します。

公開リポジトリでは全ファイルと変更履歴を閲覧できます。個人の保有数量、取得単価、損益、資産額、取引履歴、非公開メモを登録しないでください。

## 公開対象ポリシー（必須）

IDホールディングス（4709、id-holdings）は公開対象外です。再追加は本人による明示的な方針変更がない限り禁止します。保有リストの受領や全銘柄の一括更新依頼だけでは、この除外を解除しません。銘柄一覧、記事、更新予定、決算カレンダー、図表の全てが対象です。機械可読の除外指定は `_data/publication_policy.json` で管理します。

更新・公開前に `python3 scripts/validate_publication.py` を必ず実行してください。

## 決算カレンダー

`_data/earnings_calendar.json` のeventsで管理します。company_idは公開銘柄データに存在する必要があります。statusはscheduled（公式の日付付き予定）、month_only（公式の月のみ）、unknown（次回日程未確認）、fund（ETF別扱い）。scheduledにはdate（YYYY-MM-DD）、period、source、checkedが必須です。時刻は確認できた場合のみタイムゾーンを明記します。説明会、配当、決算期末を決算発表と混同しません。

as_ofは日程の確認基準日です。表示はその日時点のスナップショットで、自動収集・自動実績判定は行いません。更新時は過ぎた予定を発表済みと推定せず、公式実績を確認して整理し、as_ofとcheckedを更新してください。確認前の過去日を新しい予定表へ持ち越すことは検証スクリプトが拒否します。


## 決算記事の継続運用

- `rating` は好調・横ばい・注意・未評価のいずれか。`rating_date`（YYYY-MM-DD）と `rating_reason` を必須とし、株価評価と分けます。
- 対象期間は本文に実日付で明記。日本企業の会社年度（FY2026）と決算期（2027年3月期）、四半期単独と累計を区別します。
- `announcement` は公式発表日、`published` は公開日、`updated` は訂正・追記日。公開前レビュー中は予定の公開日を記載し、実際に承認・公開する際に日付を確認します。
- 同じcompany_id・periodを重複作成しません。新しい決算は別記事にし、同社記事へのリンクはレイアウトから自動生成します。前回の注目点・見立てを本文で検証します。
- 本人コメントは提供された言葉のみ掲載し、未提供のときは省略します。会社説明・事実・AI分析を区別します。
- 既存4社（SpaceX、Tesla、武田薬品、ファナック）の記事を維持します。アドバンス・レジデンス投資法人（3269）は本人承認後、2026年10月28日にPR #5をマージ・公開しました。MUFG（8306）は本人承認後、同日にPR #6をマージ・公開しました。SMFG（8316）は本人承認後、同日にPR #7をマージ・公開しました。JR九州（9142）は本人承認後、同日にPR #8をマージ・公開しました。ジャックス（8584）は本人承認後、同日にPR #9をマージ・公開しました。ispace（9348）は本人承認後、同日にPR #10をマージ・公開しました。CYBERDYNE（7779）は本人承認後、同日にPR #11をマージ・公開しました。伊藤忠商事（8001）は本人承認後、同日にPR #12をマージ・公開しました。続く依頼により、今回の新規分析は三菱商事（8058）1銘柄に限定します。新しいPRのマージ・公開は本人の承認後に行います。
- 第2弾の優先候補7銘柄の記事作成は一巡しました。今回の三菱商事完了後は、残り候補をユーザーへ提示するだけとし、追加の指示があるまで他銘柄の記事追加・更新に着手しません。1回の実行につき1銘柄を完成させ、既存記事の重複を避けます。他のJ-REITの新分析には本人による対象確認が必要です。
- 企業データの `legal_name` と `listing` は正式名称・国内主要上場市場の確認記録です。`listing.checked` は閲覧確認日で、資料自体の基準日や公表日とは異なります。既存の表示名や会社IDを変更せず、公開済み・更新予定の判定は記事から自動生成します。

### J-REITの記事

DPU、稼働率、賃貸収入、会社定義のNOI・FFO、資本的支出、LTV・金利・満期分布、取得・売却、次期分配予想を扱います。会計利益と分配金、積立金活用と当期の収入、予想と実績を区別します。NAV倍率は同じ基準日の投資口価格と定義を確認できる場合のみ算定します。6か月決算の前期比を企業の四半期比較と表記しません。

### 銀行・金融の記事

業務粗利益・業務純益・手数料、預貸金利回り差、貸出残高、与信費用、規制資本、配当・自己株式取得を中心に分析します。利益は管理会計と連結、一般貸倒引当金繰入前後、のれん償却前後を明記します。資金利益に含まれる投信解約損益、株式売却益、持分法利益も確認し、税引前額を純利益から単純控除して正常利益を作りません。規制上のCET1比率と会計上の自己資本比率、現行規制と完全実施試算を区別します。CF未作成の期に残高差から営業CF・FCFを推計せず、一般企業のネット負債指標を機械的に当てはめません。会社ごとの業務純益に持分法利益を含むか、部門比較が円ベースか為替影響調整後かを確認します。株式分割の前後ではEPS・配当の株数基準をそろえ、異なる基準の中間・期末配当を単純合算しません。

### ノンバンクの記事

金融費用が営業費用に含まれるかを確認し、貸倒費用を別掲する補足資料との二重計上を避けます。新規取扱高と既存契約から認識する繰延収益、国内と海外現地の決算期間、単体と連結、調達残高とオフバランス流動化を区別します。増資時はEPSの平均株数も確認します。一次資料の不一致は推測で解消せず、今回の確認方針に従い該当数値・増減評価を省略し、未解決事項と次回の確認点を残します。

### 鉄道・不動産・ホテルの記事

旅客収入は価格と輸送量を分け、月次の清算前・税込の運輸取扱収入を決算PLへ直接置き換えません。事業別の外部売上と内部取引込み収益、ホテルのADR・稼働率、賃貸の継続利益と物件販売益を区別します。災害等の期末後情報は別節にし、過去の再開予定は公式の実績確認後に更新します。復旧費の見積り、業績予想への反映、投資・金利負担を確認し、中計の複数年資金配分やEBITDAを当該四半期のCF・FCFと扱いません。

### 宇宙開発・開発段階企業の記事

売上高、営業外収益の補助金、会社独自のプロジェクト収益、実際の入金を区別します。採択・上限・当初交付決定・支払条件、契約総額と未計上額、拘束力のない潜在需要を混在させません。減損のPL区分と非現金性、研究開発費と売上原価の移行を確認し、CF未作成のQ1に残高差からFCFを作りません。流動性と純資産、借入条項の判定時点、継続企業の重要事象と重要な不確実性に関する会社判断を分け、ミッションの予定を実証済みの技術・収益へ読み替えません。訂正資料がある場合は訂正後数値を使用します。

### 医療・ロボット・戦略投資を併営する企業の記事

IFRSの報告セグメントと管理上の事業利益・本社調整を区別し、製品レンタル区分の販売・保守収益を継続課金と混同しません。事業要因と為替、費用減と粗利益、営業利益と投資評価益・税効果を分けます。医療機器承認・保険収載・臨床試験・有償利用を同一視せず、稼働台数を有償台数や患者数へ置き換えません。間接法CFの損益調整を実際の現金支出とせず、金融資産の償還と事業CF、ファンド規模・出資約束と実払込・将来の資金拠出を区別します。CFの内訳不足があればFCFの算定範囲を限定し、全事業投資を網羅したと表記しません。

### 総合商社の記事

連結収益・営業利益・持分法投資損益・親会社株主帰属利益を分け、会社独自の基礎収益をIFRS利益や独自の正常利益と扱いません。基礎収益にも市況・為替等が含まれるため増減要因を確認します。会社の巡航利益に資産回転型事業の売却損益・特殊要因を残す定義も確認し、全特殊要因と控除対象を混同しません。組織変更と社内金利ルールの変更を反映した前年比較を使用し、連結除外時の現金変動を新たな投資支払とせず、ハイブリッド資金の資本算入を含むNet DERの定義を明記します。部門組替え・取込比率変更・株式分割の比較条件をそろえます。実際のCFと運転資金等を調整した実質CF、グロス設備投資と取得売却純額、投資CFと非支配持分取得の財務CFを区別します。当年度の資金配分表と前年度配当を含む受払の対応期間、計画・決議・実行・累計基準日を明記し、未確認の必要調達額を推計しません。

### ETFは別方式（今回の記事追加対象外）

ETFは企業決算の営業利益・業績格付けを流用せず、基準価額と市場価格、ベンチマークとのトラッキング差、信託報酬等のコスト、分配と再投資を含むリターン、構成・集中度、純資産・売買流動性を中心とする別フォーマットを検討します。今回ETF記事は作成しません。

## Pull Requestの検証

`python3 scripts/validate_publication.py` と `python3 scripts/validate_articles.py` を実行します。PRの `Research and Jekyll checks` はJekyllビルド、生成HTMLの相互リンク・アンカー・CSS・動的件数、390px/1280pxの横はみ出し・HTTPエラー・表見出し・キーボードフォーカスを検証します。画面画像はActionsの `research-preview` artifactで確認できます。このworkflowにデプロイ処理はありません。公開方式は従来のmainブランチからのGitHub Pagesを維持します。

自動検証は数値が公式開示と一致することや実質的な非公開情報の不存在を保証しません。公式PDF・SEC表の期間・単位・定義と照合し、独自計算と本人コメントを手動レビューしてください。外部出典へのアクセスや未公表の次回日程など、未確認事項は記事内で明示します。
