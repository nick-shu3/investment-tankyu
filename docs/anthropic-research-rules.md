# Anthropic（ANT）投資検証・記事更新ルール

- 制定日：2026-11-20（日本時間）
- 適用範囲：投資探究のAnthropic関連記事、企業監視ページ、記事案、更新判断
- 管理元：本ファイル（`docs/anthropic-research-rules.md`）
- 関連：`AGENTS.md`、`README.md`、`_data/publication_policy.json`
- 重要：**公開リポジトリの規則文書**。未公開の個人取引・資産・認証情報・内部監視結果は記載しない。

## 1. 更新前の必須読込と優先順位

Anthropicに関する新規記事・追記・改訂・企業監視ページの更新を始める前に、毎回次を**GitHubの最新mainから再取得**する。

1. `AGENTS.md`、`_data/publication_policy.json`、本ファイル
2. `README.md`（公開・検証手順）
3. `companies/anthropic.md`（長期投資仮説と監視）
4. 既存のAnthropic記事：`_columns/anthropic-ipo-long-term-20261119.md`、`_columns/anthropic-ipo-first-day-20261120.md`、その時点で追加済みのAnthropic記事・決算記事
5. `docs/unconfirmed.md`（公開可能な未確認事項）

内容が競合した場合は個人情報・公開承認に関する制限を最優先する。ルール間の矛盾は独断で緩和せず、差分を提示して承認を求める。既存記事の数値や仮説を新事実として再通知・再掲載しない。

## 2. 8つの監視指標

| 番号 | 対象 | 重要な確認点 |
|:--|:--|:--|
| ① | Claude/API・企業顧客 | GAAP売上、API利用量、顧客数・維持率、成長率、定義と対象期間 |
| ② | 収益性 | 粗利、営業利益率、GAAP損益、黒字化、費用構造 |
| ③ | 製品・競争優位 | 新モデル、Claude Code、企業導入、実務品質・速度・価格・安全性、競合比較 |
| ④ | 計算資源・資金調達 | GPU・TPU、データセンター、提携、設備投資、リース・長期購入義務、調達 |
| ⑤ | 現金創出 | 営業CF、FCF、現金残高、資金繰り、投資・支払時期 |
| ⑥ | 法務・安全性 | 訴訟、著作権、規制、重大な安全性問題・障害 |
| ⑦ | 株式需給 | ロックアップ解除、内部者・大株主売却、増資、株式報酬・希薄化 |
| ⑧ | 株価変動 | 大幅変動の発生日・価格・騰落率・原因、企業価値への影響 |

①②④⑤は、四半期／累計、GAAP／非GAAP、売上／Run-Rate Revenue、契約金額／売上計上／現金支出を混同しない。粗利・FCFが非開示なら非開示と記載し、残高差から独自に補完しない。③は単一ベンチマークだけで勝敗を断定しない。⑦の解除日・売却額はSEC等で確認するまで推定しない。⑧の下落要因は「事業悪化／需給／市場要因／不明」に分類し、寄与度が不明なら断定しない。**SpaceXの120ドル閾値はANTに適用しない。**

## 3. 一次資料と検証手順

1. Anthropicの公式発表・決算/IR、SECのEDGAR（10-K、10-Q、8-K、目論見書、Form 4等）、Nasdaqの公式情報を優先。安全性・規制は関係当局や裁判所資料を確認する。
2. 競合比較は競合各社の公式資料を確認。Reuters等の信頼できる報道は補完資料とし、匿名情報・SNS・市場の噂は未確認として扱う。
3. 出典ごとに**原文URL、発表日、資料の対象期間、確認日（JST）**を記録。訂正資料があれば最新版と変更点を確認する。
4. 重要数値は原表の単位、会計範囲、計算式、前年比の分母を照合。推計・報道・企業の見通し・確定実績を明確に分ける。
5. 根拠が不足した場合は「未確認」とし、無理に結論を出さない。外部リンクの未検証を「確認済み」と記載しない。
6. 株価の騰落率は基準値（公開価格、前日終値、初値等）と通常取引／時間外の別を示す。株価の上下だけで売買を勧めない。

## 4. 長期投資仮説の判定

初期基準点は2026-11-19のIPO分析。少なくとも以下の4仮説を毎回意識する。

- 企業向け生成AI市場の拡大がClaudeの継続需要につながる。
- Claudeが企業・開発者市場で競争力を維持できる。
- AIエージェント普及がAPI・Claude Codeの持続的な収益に結び付く。
- 売上成長が営業利益・営業CF・投資後のFCFに転換する。

各重要ニュースの判定は **維持／要注意／再検討／判定保留**。理由、前回から変わった根拠、反証条件、次回確認点を示す。株価評価（割安・割高）と事業評価は別に扱い、適正株価の算定をしていなければ「未実施」とする。

## 5. 記事化の基準と重複回避

| 重要度 | 例 | 標準対応 |
|:--|:--|:--|
| 高 | 決算、成長率の大幅変化、巨額設備投資、FCF、重大な競争環境変化 | 根拠付きの新規記事案 |
| 中 | Claude新モデル、大型提携、重要規制・訴訟の進展 | 既存記事の追記案を優先。独立した論点なら新規記事案 |
| 低 | 日常的な株価変動、既報、軽微な製品更新 | 公開記事・通知は増やさず非公開監視記録のみ |

同じ材料の再通知・記事の重複作成を避ける。新しい決算は原則 `_articles/` に別記事、投資仮説に影響するニュースは `company_id: anthropic` を付けた `_columns/` の記事または既存記事への追記案とする。IPO当選・事業概要・競争環境の基礎説明は既存記事へのリンクを用いる。**既存記事を無断で書き換えず、何を新たに検証したかを明示する。**

## 6. 原稿の必須項目

- 読者に伝わるタイトル、要旨、情報基準日、公開日・改訂日（JST）
- **新たな事実**（出典・発表日・数値・対象期間）
- **前回との比較**（新規性・差分・既存記事へのリンク）
- **分析・推測**（事実と明確に分離）
- **8指標の該当番号、進捗、株価影響：プラス／中立／マイナス**（断定できなければ保留）
- **長期投資仮説：維持／要注意／再検討／判定保留**と理由
- リスク、反証条件、未確認事項、次の確認点
- 出典URL、独自計算式、更新履歴、投資助言ではない旨と利害関係の開示

記事内容は既存の「投資探究」の日本語文体に合わせ、断定・煽り・株価目標の創作を避ける。本人のコメントや取引行動を推測で創作しない。

## 7. 個人情報と公開承認のゲート

公開リポジトリに口座番号、残高、総資産、証券会社の通知原本、非公開の取引履歴、秘密情報を登録しない。本人が**当該記事への掲載を明示承認した項目のみ**例外として扱う。過去記事の承認は新しい記事への包括許可ではない。公開済みの個人情報も不要なら再掲しない。

重要ニュースの調査・記事案作成は自動化してよいが、**記事案の作成承認と公開承認は別**。原稿案はChatGPT Library等の非公開領域で管理し、公開リポジトリの作業ブランチ・公開PR・Issueにも、公開承認前の原稿や未承認情報を置かない。

ユーザーへタイトル・要旨・根拠・差分・レビュー方法を提示し、記事内容の明示承認を得る。公開・push・PRマージはさらに別途明示指示を受けた場合のみ実施する。非公開の調査ログや自動化成果は公開リポジトリへ書かない。

## 8. 公開・検証のチェックリスト

1. 最新mainの本ルール、`AGENTS.md`、`README.md`、公開ポリシー、Anthropic既存記事を再読。
2. 一次資料を再確認し、発表日・数値・期間・URLを検証。未確認は未確認とする。
3. 既存記事と重複・矛盾・個人情報の混入がないか確認。
4. 原稿のレビュー・掲載範囲の承認を取得し、**公開の別途指示**を確認。
5. 承認後に作業ブランチで変更、`python3 scripts/validate_publication.py` と `python3 scripts/validate_articles.py`、Jekyll/CIを実行。
6. PRの差分・出典・テスト結果を確認してからmainへマージ。失敗や未実施のテストはそのまま報告。
7. GitHub Pagesのトップ、コラム一覧、企業ページ、記事リンク、更新記録、スマートフォン表示を確認。
8. 改訂時は元の `published` を維持し、`updated` と本文更新履歴、`docs/unconfirmed.md` を更新。トップ更新記録は自動生成に任せる。

## 9. 運用ルールの変更

本ルール自体の変更は、変更理由・影響範囲・既存ルールとの差分を提示し、本人の承認を得てから更新する。変更履歴を残し、過去の判断を後から無断で書き換えない。
